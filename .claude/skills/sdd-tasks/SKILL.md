# SDD Tasks

## 使用时机
设计评审通过，准备编码或排期时。

## 输入
`spec.md`、`design.md`、当前代码与测试基线。

## 步骤
1. 按“数据/契约 → 服务 → 接口 → 前端 → 部署 → 文档”拆任务。
2. 每个任务写清改动文件、验证命令、依赖与回滚点。
3. 标注可并行任务与必须串行的迁移任务。
4. 为高风险任务增加安全、性能或兼容性专项验证。
5. 写入 `specs/<change-id>/tasks.md`。

## 输出
带 ID、依赖、验收证据和状态的任务清单。

## 门禁
- 每个任务可在一次评审中验证。
- 数据库迁移、契约变更和权限改动不得隐藏在“实现”任务中。

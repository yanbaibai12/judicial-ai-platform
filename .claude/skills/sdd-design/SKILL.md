# SDD Design

## 使用时机
规格通过评审，需要确定技术方案或跨服务改动时。

## 输入
`spec.md`、现有架构文档、数据模型、部署约束、安全要求。

## 步骤
1. 给出组件、数据流、同步/异步边界与租户隔离方式。
2. 定义接口、事件、错误码、幂等键、超时与重试。
3. 写清权限矩阵、审计字段、敏感数据处理和失败降级。
4. 评估容量、延迟、成本、兼容性与迁移路径。
5. 写入 `specs/<change-id>/design.md` 与 ADR（如需要）。

## 输出
`design.md`：上下文、方案、数据模型、接口、权限、失败与回滚、可观测性、取舍。

## 门禁
- 每个规格目标都有对应组件或接口。
- 失败路径、超时、回滚与数据迁移明确。
- 涉及外部服务必须回答数据出境与降级策略。

## 禁止
- 不得绕开租户隔离或审计。
- 不得把未验证的外部服务作为唯一主链路。

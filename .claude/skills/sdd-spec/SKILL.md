# SDD Spec

## 使用时机
收到新需求、需求变更、验收争议，或现有规格缺少可测试标准时。

## 输入
需求描述、相关文档、目标用户、现有接口、数据分类与合规要求。

## 步骤
1. 用一句话写清问题与目标，列出不做什么。
2. 识别角色、租户、数据敏感级别与失败场景。
3. 把每条需求写成 Given/When/Then 验收标准。
4. 标注依赖、风险、未决问题与需要人工确认的合规点。
5. 写入 `specs/<change-id>/spec.md`，不要直接改代码。

## 输出
`spec.md`：背景、目标、非目标、角色、场景、验收标准、数据与权限、风险、开放问题。

## 门禁
- 每条验收标准可被测试或人工核验。
- 涉及司法数据时必须写明脱敏、留存与访问范围。
- 未决问题不得进入实现阶段。

## 禁止
- 不得用“优化体验”“完善功能”等不可验收表述。
- 不得把实现方案混入规格。

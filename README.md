# 司法 AI 中台（Judicial AI Middle Platform）

> 文档版本：v1.0  
> 编写日期：2026-10-19  
> 文档状态：可运行试点版（生产验收进行中）
> 建设依据：项目四「司法 AI 中台」介绍

## 1. 平台定位

司法 AI 中台是公司级 AI 能力平台。它面向公司多条业务线和法院内网环境，统一沉淀**模型推理、RAG/GraphRAG 检索、视觉识别、MCP 工具、AI 数据治理和 AI 研发流程**，通过标准接口、SDK 与 MCP 协议，为传统业务系统、AI 应用和 Agent 提供可复用、可计量、可审计、可版本化的 AI 能力。

平台本身**不承载具体审判业务逻辑**，而是把各业务线重复建设的模型接入、检索链路、工具调用和数据治理能力收敛为公共基础设施。

## 2. 建设目标

1. **统一模型服务**：以 Qwen3-8B 为基座，采用「单基座 + 多 LoRA Adapter」方式承载多类司法任务，降低多模型独立部署带来的显存占用与运维成本。
2. **统一公共检索**：基于 Milvus + Neo4j 提供混合召回、Rerank、引用溯源和图谱检索能力，并对知识库、索引、检索配置做版本管理。
3. **统一能力入口**：将模型推理、RAG、视觉识别、MCP 工具统一注册、统一鉴权、统一限流、统一计量、统一审计。
4. **统一数据闭环**：采集模型输出、用户反馈和检索记录，经质量筛选、模型预审、人工复核后沉淀为训练集、评测集、Bad Case 数据集和知识版本，形成持续迭代机制。
5. **统一研发流程**：基于 Claude Code 自研 Forge SDD，将需求、设计、开发、评审和验收沉淀为标准 Skills，结合 MCP 接入设计稿、文档和内部工具，形成统一的 AI Coding 研发规范。

## 5. 关键设计决策摘要

| 决策 | 结论 | 理由 |
|---|---|---|
| 能力接入方式 | OpenAI 兼容接口 + 平台统一调用接口 + MCP | 降低存量系统迁移成本，同时覆盖 Agent 工具调用场景 |
| 模型部署方式 | 单 Qwen3-8B 基座 + 多 LoRA Adapter | 多任务共享基座权重，显著降低显存与加载开销 |
| 检索架构 | Milvus 向量/稀疏检索 + Neo4j 图谱检索 | 兼顾语义召回、关键词召回和关系推理 |
| 检索增强 | 混合召回 + RRF/加权融合 + Rerank | 提升司法长文本、专有名词和类案场景的召回质量 |
| 知识版本 | 知识库版本、索引版本、检索配置版本相互独立 | 支持灰度、回滚和可复现评测 |
| 数据闭环 | 全量留痕 + 质量筛选 + 模型预审 + 人工复核 + 数据集版本化 | 保证训练/评测数据可追溯、可复现 |
| 多租户 | 逻辑隔离为主，敏感租户支持物理隔离 | 平衡成本与司法数据安全要求 |
| 部署形态 | Docker Compose 开发，Kubernetes 生产，GPU 节点池 | 满足私有化交付和弹性扩缩容 |
| 研发流程 | Forge SDD：需求→设计→任务→实现→评审→验收 | 把 AI Coding 纳入可审计的工程流程 |

## 7. 代码实现与快速开始

仓库已包含可运行的 MVP，优先保证无 GPU、无 Docker 的本地环境也能跑通核心链路：

```bash
uv sync --dev --extra production
uv run python -m judicial_ai.seed
uv run python -m alembic upgrade head
uv run uvicorn judicial_ai.main:app --reload --port 8080
```

- 完整启动、配置和调用示例：[DEVELOPMENT.md](DEVELOPMENT.md)
- 本地默认：SQLite + 内存限流 + Mock 推理；生产使用 MySQL/Redis/Milvus/Neo4j/vLLM
- 管理控制台：`http://127.0.0.1:8080/`；OpenAPI：`/docs`
- 异步 Worker：`JOB_MODE=worker uv run python -m judicial_ai.worker`
- 容器编排：[deploy/compose/docker-compose.yml](deploy/compose/docker-compose.yml)
- K8s/Kustomize：[deploy/k8s/base](deploy/k8s/base)
- 生产就绪矩阵：[docs/12-生产就绪矩阵.md](docs/12-生产就绪矩阵.md)

已实现：能力注册/发布/授权、统一网关、OpenAI 兼容 Chat/Embeddings/Rerank/SSE、知识库与混合检索、引用溯源、原件归档/哈希/授权下载/保留期删除恢复、应用权限 scope、索引审批与显式生产别名、跨存储补偿和对账恢复、MCP 工具注册与调用、反馈/Bad Case/数据集、用量与审计、AI 数据治理闭环、Milvus/Neo4j/Redis 适配器、异步 Worker、OIDC/LDAP、权限与安全头、Prometheus 指标、Alembic、K8s/备份/CI、Python/Java SDK、Forge SDD Skills。

仍需外部环境验收：真实 Milvus/Neo4j/Redis/vLLM 联调、IdP/LDAP 联调、MySQL 迁移回滚、K8s 集群部署、生产等价压测和恢复演练；法律规则、业务金标准数据集与 UAT 必须由授权人员审核签字。JEV 仍仅 shadow；ReFRAG 为应用层压缩，不包含论文的 CPT/RL/decoder 改造。

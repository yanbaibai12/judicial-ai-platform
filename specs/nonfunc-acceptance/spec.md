# 规格：非功能与运维验收（RTO/RPO、联合恢复、故障演练、压测与稳定性）

- change-id：`nonfunc-acceptance`
- 状态：待评审
- 关联：docs/09-部署与运维.md、docs/12-生产就绪矩阵.md、docs/15-企业级加固验收记录.md、tests/performance/README.md
- 必载 Skills：`sdd-acceptance`、`security-review`

## 1. 背景与问题

当前非功能验收为空白，无法对"能否上线"给出可签字结论：

1. RTO/RPO 没有认定口径与实测记录；
2. 数据库迁移与回滚没有演练剧本；MySQL 从未做过 failover 与降级双向验证；
3. 数据库、对象存储、Milvus、Neo4j **联合恢复**从未做过；单点中断演练缺失；
4. 没有生产等价硬件的压测，P95 无实测值；
5. 没有 8 小时稳定性数据（错误率、内存增长、任务丢失、数据污染）；告警触发到值班闭环未验证；
6. 缺签字验收表（技术、安全、法律、业务、运维五方）。

## 2. 目标

1. 给出可复现的 RTO/RPO **实测**剧本与判定门槛，形成签字证据。
2. 建立单点中断、迁移回滚、联合恢复、压测、稳定性五大演练剧本，每个剧本自带观察指标与失败判据。
3. 建立证据归档目录结构与签字表模板，使"本期非功能验收是否通过"有可核验答案。

## 3. 非目标

- 本期不直接在生产环境执行演练；产出的是**剧本 + 判定门槛 + 证据模板**。
- 不替代功能验收、安全验收与法律人工审定。
- 不承诺未冻结的硬件规格上的性能数值。

## 5. 场景与验收标准

### 5.1 RTO/RPO

- **AC-1.1（MySQL RTO ≤30 分钟）** Given 主库调协，When 从库升主、应用重新连接，Then **从故障注入到应用恢复可写**的墙钟时间 ≤ 30 分钟，记录 `t_detect`、`t_failover`、`t_reconnect`、`t_app_ready` 四个时间点。
- **AC-1.2（Redis RTO ≤5 分钟）** Given Redis 主下线，When Sentinel 选主完成，Then 依赖 Redis 的限流/缓存在 **≤5 分钟**内恢复服务，期间允许限流退化但不可 5xx。
- **AC-1.3（原件与元数据 RPO ≤5 分钟）** Given 以 5 分钟为 RPO 目标，When 触发恢复演练，Then 与最近 5 分钟窗口内相比，最多允许 ≤5 分钟的写入丢失，**已确认上传不得无记录丢失**：即上传返回 2xx 的每条数据必须在恢复后可见，否则一律判 P0 缺陷。
  - 判定方法：上传前写入 `upload_ack` 流水（含客户端生成的 `idempotency_key` + 服务端返回的 `document_id` 与 `created_at`），恢复后逐条比对。
  - **口径待会签**：5 分钟为默认建议值，需运维与业务负责人共同确认后冻结。

### 5.2 单点中断

- **AC-2.1** Given 对每个组件（数据库/缓存/模型/向量库）分别注入故障，When 观察 60 秒，Then 采集到的状态码分布、`degraded_reason`、熔断开合、告警触发时间与自动化处置动作均与预期一致，无未预期的 5xx 连锁。
- **AC-2.2** Given 恢复动作，When 被注入组件恢复，Then 服务在各自 RTO 内回到 `readyz=200`，且积压任务被消化（不出现任务丢失）。

### 5.3 联合恢复

- **AC-3.1** Given 四路（数据库、对象存储、Milvus、Neo4j）同时中断，When 按固定顺序恢复，Then 全量可服务时间 ≤ 60 分钟；数据对账（与 `upload_ack` 流水、索引快照、图谱重建）全部一致。
- **AC-3.2** Given 恢复完成，When 校验，Then 不出现：重复上传、凭空出现新记录、索引与库内容不一致、图谱节点缺失被引用的情况。

### 5.4 MySQL 迁移与回滚

- **AC-4.1** Given 生产等价数据（脱敏）与下一版本迁移脚本，When 执行 `alembic upgrade head`，Then 迁移时间 ≤ 30 分钟，迁移中应用可读（可写窗口按评测记录）。
- **AC-4.2** Given 迁移后版本回退需求，When 执行 `alembic downgrade`，Then 回滚 ≥ ≤ 20 分钟，且**数据不丢失**、降级后的旧版本可正常服务。
- **AC-4.3** Given 迁移过程中应用双版本并行，Then 不报 `ProgrammingError` 或契约破坏（迁移需前向兼容 ≤1 版本）。

### 5.5 压力测试

- **AC-5.1（硬件等价）** Given 压测环境，Then CPU/内存/GPU/磁盘 IOPS/网络带宽与生产规格一致，且记录拓扑图与配置；否则测试结论作废。
- **AC-5.2（数据等价）** Given 压测语料，Then 选用脱敏或合成语料，量级为生产预估的 1.2 倍。
- **AC-5.3（性能门槛）** Given 稳态压测 ≥ 30 分钟，Then 检索（含混合召回、重排、引用）P95 ≤ **500 ms**；写路径（上传+索引）P95 ≤ **2 s**；错误率 < 0.5%。
- **AC-5.4（停止条件）** Given 达到目标 QPS 或错误率超阈值，Then 压测停在记录点，并计算最大稳定 QPS。

### 5.6 稳定性测试

- **AC-6.1（8 小时）** Given 连续 8 小时压测，Then 全程错误率 < **0.5%**；无持续内存增长（RSS 斜率 ≤ 1 MB/h）；无任务丢失（以 `task_id` 对账）；无数据污染（重复执行校验一致）。
- **AC-6.2** Given 过程中采样，Then 每 5 分钟采集一次内存/线程/GPU 显存/队列长度并入库；任一指标 P99 超阈值需标注分析。

### 5.7 告警与值班

- **AC-7.1** Given 故障注入，Then 告警在预期时间内到达值班通道；若通道未达，判演练失败。
- **AC-7.2** Given 值班交接，Then 建立并演练 checklist，含告警认领、判断、升级、恢复、复盘五个环节；每次演练至少完成一次交接记录。

## 6. 数据与合规

- 压测与演练语料必须脱敏或合成；含真实当事人、身份证号、联系方式、案号的材料一律禁止入压测环境。
- 演练证据包：日志、快照、报告；导出前脱敏；证据包中禁止出现连接串明文、令牌、KMS Key、内部主机名与回显口令。
- 地址/凭证配置走密钥管线，不进入证据包。
- 证据归档要求每个证据带上时间戳、`git_sha`、配置变更编号、执行人、复核人。

## 7. 依赖与风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 硬件规格未冻结，性能结论不可信 | 高 | 剧本能拿到规格图与配置清单才能出报告 |
| RTO/RPO 数字未经会签 | 高 | 标注"待会签"，强制运维+业务负责人签认后才冻结 |
| 联合恢复顺序影响对外承诺 | 中 | 提供两种顺序剧本（顺序 vs 并行），对比结果择优 |
| 演练期间损坏生产数据 | 高 | 仅在隔离环境执行；恢复脚本先可观测再允许动作 |
| 指标采集本身影响压测 | 中 | 采集降频；采集降级不阻塞主流程 |

## 8. 开放问题

1. **RTO/RPO 具体数值**：MySQL RTO ≤30 分钟、Redis RTO ≤5 分钟、原件与元数据 RPO ≤5 分钟为默认建议，**需运维与业务负责人会签确认**；界阈值发现不符再统一调整。
2. 压测 GPU/硬件规格未定，故**只冻结口径不冻结数值**；压测结论待硬件规格批复后单独出具。
3. 8 小时是最低门槛还是 24 小时？默认 8 小时；若业务方要求 24 小时，须在签字前调整剧本与样本。

## 9. 手工确认项

- 运维负责人 + 业务负责人会签 RTO/RPO 数值。
- 安全负责人确认脱敏规则与证据包脱敏范围。
- 五方（技术、安全、法律、业务、运维）最终签字；不适用项须附书面范围依据（对应验收矩阵 A01–A15）。

# 规格：脱敏司法评测集与检索业务质量量化

- change-id：`biz-quality-eval`
- 状态：待评审
- 关联：docs/05-公共检索服务.md（引用回溯与引用保真）、docs/06-AI数据治理闭环.md（脱敏、数据集版本、评测）、docs/12-生产就绪矩阵.md
- 必载 Skills：`judicial-domain`、`rag-design`

## 1. 背景与问题

平台已有混合召回、重排、引用溯源、上下文压缩与 GraphRAG 能力，`src/judicial_ai/services/governance_pipeline.py` 内也已有 `retrieval_metrics` 与 `answer_overlap` 这类指标纯函数，但**整条业务质量链路无法被度量**：

1. 没有经脱敏授权的司法评测集，检索效果好坏只能靠主观感受；
2. 标注没有版本号，换人重标结果无法对比，也没有法律专家裁决记录；
3. Recall@10、引用准确率、拒答准确率、误报/漏报没有统一判定口径，无法写进验收报告；
4. 没有"难例分层"，无法回答"在哪些场景上还不行"；
5. 评测不可重复，同版本重跑对不齐，回归对比没有可信基线。

## 2. 目标

1. 建立**合成或经授权脱敏**的司法评测集，六类场景全覆盖，可版本化、可回溯、可对比。
2. 建立版本化标注流程，含标注员、法律专家裁决、争议仲裁与一致性度量。
3. 建立可重复的评测指标流水线，输出 Recall@10、引用准确率、拒答准确率、误报/漏报与场景分桶结果。
4. 把指标结果入库并生成评分卡，支持两版本之间的环比对比。
5. 使"当前检索能力能否上线"这个问题有可核验的答案。

## 3. 非目标

- 不实现新的召回/重排算法（属 `rag-design` 与目标架构改造的范畴）。
- 不做真实 GPU/vLLM 推理压测（属 `target-architecture`）。
- 不替代法律专家的人工审定，只提供给专家判断用的证据与口径。
- 不负责合规数据采集流程本身，只规定"进评测集的数据必须满足什么条件"。
- 不做训练语料的构建。

## 4. 角色与权限

| 角色 | 职责 | 权限边界 |
|---|---|---|
| 评测负责人 | 组织评测、冻结基线、出具评分卡 | 可读写评测集版本与评测结果；不得改标注口径单方面变更 |
| 标注员 | 按口径标注 query 与引用 | 可写标注草稿；不得把自己标注直接定稿 |
| 法律专家 | 复核标注、裁决争议、签字 | 可写裁决结论与适用边界说明；不得绕过脱敏规则提交语料 |
| 平台研发 | 实现流水线、修复问题 | 可读评测结果；不得改写历史评测结果 |
| 审计人员 | 只读核验脱敏与留存合规 | 只读；禁止导出含可识别原文的片段 |

数据分级：评测集语料、标注、评测结果均为敏感数据，落地加密或受限目录；导出需审批；不得含真实当事人、身份证号、联系方式、真实案号、未脱敏裁判文书。

## 5. 场景与验收标准

### 5.1 评测集可版本化

- **AC-1.1** Given 一份新建评测集，When 执行版本冻结操作，Then 生成不可变 `dataset_version`，含内容哈希、创建人、创建时间、脱敏规则版本号。
- **AC-1.2** Given 已冻结的评测集版本，When 任何写入被尝试，Then 拒绝写入，并在审计日志留下 `dataset.version.write_rejected`。
- **AC-1.3** Given 两个评测集版本，When 执行对比，Then 输出增量样本清单（新增/删除/修改）与脱敏规则版本差异。

### 5.2 六类场景全覆盖

- **AC-2.1** Given 评测集，When 按 `scenario` 统计，Then 常见问题、难例、无答案（应拒答）、旧版本依据、权限受限、冲突依据六类场景都有样本，且每类样本数 ≥ 20。
- **AC-2.2** Given "无答案"样本，When 评测时系统未拒答而是生成了结论，Then 判为拒答错误（假阳）。
- **AC-2.3** Given "权限受限"样本，When 用无该权限的身份检索，Then 输出不得包含无权限可见的引用片段，命中即判为越权泄露并单独告警。

### 5.3 评测指标

- **AC-3.1（Recall@10）** Given 评测集某场景样本，When 执行检索评测并按 `retrieval_metrics` 口径计算，Then Recall@10 单场景 ≥ 0.90 才算通过门槛，全局加权结果同时给出。
- **AC-3.2（引用准确率）** Given 生成式回答的引用列表，Then 每条引用句必须能命中检索结果中真实存在的片段（连同分句连续性），未命中记为幻觉引用。引用准确率 ≥ 0.95。
- **AC-3.3（拒答准确率）** Given 混淆矩阵定义（应拒答却答=FP_API；应答却拒=FN_API），Then 无依据拒答准确率 = (TN_API) / (TN_API + FP_API) ≥ 0.90。
- **AC-3.4（误报/漏报）** Given 检索判定，Then TP/FP/FN/TN 判定规则明确：TP 为检索命中且引用有效，FP 为检索命中但引用无效或与标注无关，FN 为标注相关但未被 top-10 检索到，TN 为不相关且未被检索到。
- **AC-3.5（难例分层）** Given 样本的 `difficulty_score`，Then 评测报告按 5 档分桶输出各指标，且难例桶（≥4）单独给出结论。
- **AC-3.6（分桶输出）** Given 六类场景，Then 评测报告按场景分桶，每桶给出样本数与 Recall@10/引用准确率/拒答准确率三项指标。

### 5.4 可重复性

- **AC-4.1** Given 同 (`dataset_version`, `index_version`, `prompt_version`, `model_version`)，When 重跑评测，Then 各指标差异不超过 0.01（浮点容差），且引用命中集合一致。
- **AC-4.2** Given 评测结果，When 生成评分卡，Then 评分卡含 `git_sha`、`migrations_head`、各版本号、时间戳与执行人，任何缺失即判不合格。

## 6. 数据与合规

| 要求 | 规定 |
|---|---|
| 语料来源 | 只允许合成数据，或经数据负责人书面授权的脱敏业务数据 |
| 禁止进入 | 真实当事人姓名、身份证号、联系方式、真实案号、未脱敏裁判文书、真实犯罪记录 |
| 脱敏规则 | 规则版本化，记入 `dataset_version.redaction_rules_version`；升级规则必须新建版本，不改旧版 |
| 脱敏映射 | 加密存于独立目录，权限最小化；评测集副本与映射表物理隔离 |
| 训练隔离 | 带映射表的可逆数据**严禁**流入训练数据集（`judicial-domain` 约束） |
| 留存 | 评测原始请求默认只留存摘要与 hash，不保留完整 prompt；留存期默认 180 天 |
| 导出 | 估值报告导出需审计；报告正文与附件均需二次脱敏扫描 |
| 访问范围 | 评测负责人、法律专家、授权研发；审计只读；其余拒绝 |

## 7. 依赖与风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 标注口径不一致导致指标虚高 | 高 | 双人独立标注 + Cohen's kappa 一致性门槛（≥0.7 才生效），争议由法律专家仲裁 |
| 评测集覆盖不全，指标失真 | 中 | 六类场景各 ≥20 样本；制定补充入库流程 |
| 指标被"刷分" | 中 | 评测集对研发隐藏 labels 副本；禁止按评测集调参后立即内测，需走基线对齐流程 |
| 脱敏不彻底，敏感信息外泄 | 高 | 导出二次扫描；法律专家抽检；违规入库即刻停用评测集版本 |
| 法律专家之间定性分歧 | 中 | 仲裁机制；争议记录进 `dataset_version.adjudications`，不删除原始分歧 |
| "无答案"场景标签定义模糊 | 中 | 采用"该期限届满才知道"式口径；实际判定标准写入 annotation_rules 并版本化 |

## 8. 开放问题

1. 评测调用走哪个身份是否需要单独的 `eval-runner` 账号？本规格默认走平台管理员身份执行评测；若安全评审要求最小权限的专用账号，属独立变更。
2. 模型接口超时失败的样本是否算统计分母？本规格默认：调用超时的样本判为**执行失败**，不计入指标分母，单独报告执行失败率，且执行失败率本身作为评测有效性门槛。
3. 无依据拒答准确率是否按场景加权？本规格默认按场景均值加权（样本幂权重），并在报告同时给出未加权结果。

以上三项不阻断实现，已选定口径随设计固定。

## 9. 人工确认项

- 由数据负责人书面确认评测集全部样本的脱敏授权范围。
- 由法律专家确认"冲突依据""旧版本依据"两类场景的判定口径。
- 由安全负责人确认留存期 180 天与导出审批流程。

# 01 项目概述

## 1. 背景

公司多条业务线在建设 AI 应用时，普遍存在以下重复投入和治理问题：

1. **模型重复接入**：各业务线分别部署通用大模型、分类模型、视觉模型，GPU 资源碎片化，版本不统一。
2. **RAG 重复建设**：文档解析、切分、向量化、召回、重排、引用溯源各自实现，效果和稳定性参差不齐。
3. **工具调用链路重复**：业务系统、MCP 工具、RAG、GraphRAG 的鉴权、参数校验、超时重试、结果标准化由各 Agent 重复实现。
4. **数据无法沉淀**：模型输出、用户反馈、检索记录散落在各业务库，难以形成训练集、评测集和 Bad Case 资产。
5. **研发流程不统一**：AI 辅助编码缺少需求、设计、评审、验收的标准动作，代码质量和安全边界依赖个人经验。

司法 AI 中台的建设目标，是把上述能力收敛为公司级公共基础设施，支撑传统业务系统、AI 应用和 Agent 的多业务复用。

## 2. 建设目标与成功标准

### 2.1 业务目标

| 目标 | 说明 |
|---|---|
| 降低重复建设 | 新业务线接入模型、检索、工具能力时，不再自建推理与 RAG 基础设施 |
| 缩短接入周期 | 标准能力接入从「周级」缩短到「天级」 |
| 提升回答质量 | 通过混合召回、Rerank、引用溯源和领域 LoRA 提升司法场景准确性 |
| 沉淀数据资产 | 基于千万级司法业务数据持续构建训练集、评测集、Bad Case 数据集和知识资产 |
| 支撑 Agent 生态 | 为智能受理、智能调解等 Agent 提供统一模型、检索和工具运行时 |
| 满足私有化合规 | 支持公司环境和法院内网私有化交付，数据不出域、全程可审计 |

### 2.2 北极星指标（建议）

| 指标 | 定义 | 首年目标（建议） |
|---|---|---|
| 能力复用率 | 调用方中复用中台既有能力（而非自建）的业务线占比 | ≥ 80% |
| 平均接入周期 | 从提出接入到生产可用的自然日 | ≤ 5 个工作日 |
| 模型服务可用性 | 推理服务成功请求 / 总请求 | ≥ 99.5% |
| 检索命中率 | 评测集 Recall@10 | ≥ 0.90 |
| 引用准确率 | 引用片段可定位且与结论相关 | ≥ 0.95 |
| 数据闭环时效 | 反馈产生到进入可评测数据集 | ≤ 72 小时 |
| Bad Case 关闭率 | 已定位并完成回归验证的 Bad Case 占比 | ≥ 90% |

> 上述指标为立项基线，需在首批业务线试点后校准。

## 3. 平台范围

### 3.1 范围内（In Scope）

- AI 能力注册、发现、版本、授权、计量与审计。
- 统一模型推理服务：大语言模型、LoRA Adapter、Embedding、Rerank、视觉/OCR。
- 公共检索服务：知识库管理、文档解析、混合召回、图谱检索、引用溯源、检索配置与版本管理。
- MCP 工具接入与统一调用：工具注册、参数校验、鉴权、超时重试、幂等、审计。
- AI 数据治理：反馈采集、质量筛选、模型预审、人工复核、数据集与 Bad Case 管理。
- Forge SDD 研发流程：Skills、MCP 集成、质量门禁、产物归档。
- 管理控制台：能力、模型、知识库、数据集、应用、配额、审计的可视化管理。
- 私有化部署、可观测性、备份恢复和安全合规能力。

### 3.2 范围外（Out of Scope，v1）

- 具体审判业务办理流程（立案、排期、庭审、结案等）。
- 业务系统的案件数据模型和业务规则。
- 大模型预训练和全量微调平台。v1 负责**数据集生产与版本管理**，训练任务可由外部训练平台执行。
- 通用 BI、报表和数据仓库建设。
- 面向公众的互联网服务。
- 自研向量数据库、图数据库或推理引擎。

### 3.3 与其他平台/系统的关系

| 系统 | 关系 |
|---|---|
| 业务系统（立案、审判、执行、调解等） | 通过 SDK/OpenAPI 调用中台能力；也可将业务能力注册为 MCP 工具供 Agent 使用 |
| Agent Harness（智能受理、智能调解等） | 复用中台的模型、检索、工具运行时；Guardrails、Trace 可在 Agent 侧或中台侧协同 |
| 训练平台 | 消费中台产出的数据集版本，回传训练后的模型/LoRA 产物 |
| 统一身份认证 | 提供 OAuth2/OIDC 或企业级 SSO，中台做租户与应用授权 |
| 日志/审计平台 | 接收中台审计日志、调用日志和安全事件 |
| 法院内网基础设施 | 提供 GPU、存储、网络、数据库和容器平台 |

## 5. 核心业务场景

### 5.1 智能问答与法律咨询辅助

业务系统将用户问题发送至中台，中台完成意图识别、知识检索、重排、Prompt 组装和模型生成，返回答案及引用来源。

### 5.2 文书辅助生成与校对

基于案由、事实要素和法律法规，生成文书草稿或校对建议；通过领域 LoRA 提升格式与术语一致性。

### 5.3 类案检索与要素提取

使用 Milvus 做语义/关键词混合召回，使用 Neo4j 做当事人、案由、法条、裁判要点之间的关系扩展，返回类案列表和相似理由。

### 5.4 视觉识别与材料解析

对扫描件、照片、PDF 进行 OCR、版面分析、要素抽取和图像分类，输出结构化结果。

### 5.5 Agent 工具调用

Agent 通过 MCP 协议发现并调用中台注册的工具；中台统一处理鉴权、参数校验、超时重试、结果标准化和写操作幂等。

### 5.6 数据回流与持续优化

采集模型输出、用户点赞/点踩/修正、检索记录和人工复核结果，形成 Bad Case 与数据集版本，驱动模型和 RAG 迭代。

## 6. 术语表

| 术语 | 说明 |
|---|---|
| Capability | 中台对外提供的一项能力，如对话模型、检索、OCR、MCP 工具 |
| Capability Version | 能力的不可变版本，支持灰度与回滚 |
| Adapter / LoRA | 低秩适配器，在共享基座上承载特定任务能力 |
| RAG | 检索增强生成 |
| GraphRAG | 结合知识图谱的检索增强生成 |
| Hybrid Retrieval | 稠密向量、稀疏向量/BM25、图谱等多路召回融合 |
| Rerank | 对召回结果进行精排 |
| Citation | 引用溯源信息，包含文档、页码、段落、片段 |
| KB Version | 知识库版本，描述某一时点的文档与知识范围 |
| Index Version | 索引版本，描述向量/图谱索引的构建快照 |
| Retrieval Config | 检索配置，包含召回路数、融合权重、阈值、Rerank 模型等 |
| Bad Case | 输出错误、引用错误、拒答不当或用户明确否定的案例 |
| MCP | Model Context Protocol，模型与工具/数据源之间的标准协议 |
| Forge SDD | 基于 Claude Code 的需求/设计/开发/评审/验收标准化研发流程 |
| Tenant | 租户，通常对应业务线、法院或项目 |
| Application | 调用中台能力的业务应用，拥有独立凭证与配额 |

## 7. 约束与假设

### 7.1 约束

1. **私有化部署**：生产环境部署在公司环境或法院内网，默认不依赖公网 SaaS。
2. **数据安全**：司法数据分级分类，敏感数据不出域；所有调用可审计。
3. **GPU 资源有限**：需要通过单基座 + 多 LoRA、量化、批处理等手段提升资源利用率。
4. **存量系统多样**：需要同时支持 HTTP/OpenAPI、SDK、MCP 等接入方式。
5. **合规要求**：遵循等保、数据安全和个人信息保护相关要求，具体等级以安全部门评审为准。
6. **模型可控**：仅接入经过评测和备案的模型；模型、LoRA、Prompt 模板均需版本化。

### 7.2 设计假设（需确认）

| 编号 | 假设 | 影响 |
|---|---|---|
| A1 | 生产环境可提供至少 2 张 48GB 以上 GPU 用于对话模型，另有余量用于 Embedding/Rerank | 推理容量与高可用方案 |
| A2 | 业务系统以 Java/Spring Boot 为主，需提供 Java SDK | SDK 优先级 |
| A3 | 知识库文档以 PDF、DOCX、扫描件为主 | 解析与 OCR 流水线 |
| A4 | 首批试点业务为智能受理、智能调解或类案检索 | 里程碑排序 |
| A5 | 训练任务由外部训练平台执行，中台只负责数据集与评测 | 范围边界 |
| A6 | 法院内网允许部署 Milvus、Neo4j、MySQL、Redis 和容器平台 | 部署架构 |
| A7 | 统一身份认证可提供 OIDC/OAuth2 或 LDAP 对接 | 认证方案 |

## 8. 交付物

1. 司法 AI 中台平台软件（网关、注册中心、模型服务、检索服务、数据治理、管理控制台）。
2. OpenAPI 契约、Python/Java SDK、MCP Server/Client 接入规范。
3. 部署包（Docker Compose、Helm Chart/K8s manifests）和运维手册。
4. 数据模型、表结构、初始化脚本和迁移脚本。
5. 测试报告：功能、接口、性能、检索效果、模型效果、安全。
6. Forge SDD Skills 包和研发流程规范。
7. 试点业务接入案例与验收报告。

## 9. 验收总原则

平台验收分为四类：

- **功能验收**：能力注册、调用、检索、数据闭环、权限审计等功能完整可用。
- **性能验收**：网关开销、推理吞吐、检索延迟、并发能力达到基线。
- **效果验收**：在双方确认的评测集上达到召回、引用、生成质量目标。
- **安全合规验收**：权限、审计、加密、脱敏、数据保留满足安全评审要求。

具体指标见 [10-开发计划与验收](10-开发计划与验收.md)。
